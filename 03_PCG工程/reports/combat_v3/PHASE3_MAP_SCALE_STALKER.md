# Phase 3 地图缩放对象位置与潜行者调试

本模块修复人工试玩中 `Map Size` 不为 1 时的两个坐标错误。弹药的交互点已经
使用缩放坐标，但黄色模型仍画在原始 Layout 坐标，导致显示位置和真实拾取位置
分离。潜行者分裂位置从运行中的 Boss 世界坐标计算，旧代码在创建角色时又将
该坐标乘一次 `Map Size`，会使潜行者偏离 Boss，严重时落到外墙之外。

现在所有静态 Layout 位置统一通过 `point()` 转换到世界坐标。弹药模型的位置
随地图缩放，但模型半径和高度不变。潜行者候选点直接使用已缩放的世界坐标，
不再二次缩放；原有向下地板射线和胶囊碰撞检查继续执行，因此无合法候选时仍
明确报告失败，不在墙外强制生成。

Main Inspector 新增 `Stalker` 分组：

- `Stalker Speed` 默认 4.8 模型米/秒；
- `Stalker Damage` 默认每次 20；
- 玩家测试生命默认 100。潜行者完成预警攻击后扣血并继续施加原有短暂控制，
  攻击事件记录伤害和剩余生命；生命归零时记录死亡。

这些数值属于 Phase 3 人工试玩参数，正式评分冻结时必须锁定并使用新的配置
哈希，不能与此前校准结果混排，也不进入遗传基因。

## 验证

- Godot 4.7.2，真实 Layout v5 Seed 6，`Map Size=1.5`：弹药模型与缩放后的
  交互点重合；潜行者出生的 X/Z 平面位置保持在 Boss 规定偏移内；角色和弹药
  模型自身尺寸未缩放。
- 同一测试确认 Inspector 的速度 6.4 实际成为潜行者移动速度，单次伤害 17
  正确从玩家生命扣除。
- 完整 Godot 机制回归通过，覆盖射击、撞门、补给、换弹、分裂和第二阶段击杀，
  `issues=[]`。
- `python -B -m unittest discover -s combat_pcg -t .`：63 项通过。

本测试只证明坐标和参数接线正确，不代表 4.8／20 已完成战斗难度校准。
