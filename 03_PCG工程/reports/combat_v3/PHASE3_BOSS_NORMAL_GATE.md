# Phase 3 缩放地图的 Boss 普通门穿越修复

## 原因

上一模块处理的是 `through`／`break` 撞门触发，不覆盖普通 `normal` 门。
Seed 177、`Map Size=1.5` 的普通门净宽约 2.19–2.25 米，Boss 胶囊直径约
1.16 米；门洞碰撞扫掠无阻挡，Boss 导航路径也包含启用的普通门连接。

实际故障位于 `_boss_waypoint`：它只检查距离当前点不超过固定 2.0 米的前方
路点。普通门两端的导航连接原长约 1.5 米，放大后约 2.25 米。Boss 到达入口
后无法选择出口端点，下一帧又选回入口附近的投影点，于是门口反复抖动而不
跨越。

## 修复

Boss 的物理安全前瞻改为 `2.0 × layout_scale`。该值只控制候选路点范围，
不会缩放 Boss 速度、胶囊或门洞。每个候选仍必须通过 `test_move` 的完整胶囊
扫掠；隔墙或转角不可直达时不会跳过墙体。

## 验证

- 修复前，Seed 177 的六个普通门均停在入口导航端点；导航连接启用、路径
  存在、胶囊门洞扫掠无阻挡。
- 修复后，`gate_0`、`gate_2`、`gate_3`、`gate_4`、`gate_8`、`gate_10`
  均从门前房间内部接近，并由真实 Boss 胶囊跨过门洞中线。
- Seed 177、`Map Size=1.5` 的 Inspector／物理回归通过。
- 完整 Godot 战斗机制回归通过：`issues=[]`，仍覆盖撞门、补给、换弹、
  分裂和第二阶段胜利。
- `python -B -m unittest discover -s combat_pcg -t .`：63 项通过。

本修复只恢复普通门的尺度一致穿越，不将普通门改为可破坏门，也不改变战斗
参数或正式评分口径。
