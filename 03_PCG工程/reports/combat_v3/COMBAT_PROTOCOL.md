可机读文件：combat_pcg/combat_config.json。所有新战斗数值均为研究假设，不是官方鼠王参数，未校准、不可正式实验。

现有玩家半径.35、Boss半径.58模型米作为初值，玩家速度5 m/s；新增Boss速度4.2 m/s、HP1000，单发40伤害，.3秒射速、.35秒瞄准、2秒换弹、8发弹匣；初始总弹12含装填，6包x8=48，合计60发，理论总伤害2400。固定1把研究武器，只用于建立可比较射击行为。命中必须受相机感知、枪口射线、范围与角误差影响，不能“可见即自动扣血”。

80度普通FOV、55度瞄准FOV、反应.25秒等均需敏感性校准。事件按实际发生时间处理；同一精确时刻致死命中和有效抓取相撞时死亡优先，日志必须标记该平局，禁止不同引擎不同口径。

## 同一逻辑步事件裁决（Phase 1.4确认的草案合同）

输入是已带合法性证据的事件提案。排序固定为：**有效抓取 → Boss撞开Portal → 换弹完成 → 拾取完成 → 开枪 → 命中/扣血 → 分裂或胜利 → 超时**。终止后不再应用其余提案。门在同一步打开后，射击仍须重新检查枪口LOS；不得沿用开门前或相机可见的结果。换弹完成先于同一步开枪；死亡先于同一步拾取。有效抓取与致死一枪时间完全相等时死亡；一枪致死与超时同一步时胜利。实际实现需记录逻辑步编号、稳定事件序号及数据，不靠Godot信号/线程回调顺序。

**用户于2026-11-21明确：必须进入第二阶段后才能彻底击杀鼠王。** 首阶段一枪越过分裂阈值甚至理论上打到零时，将Boss血量夹到阈值（草案为50%=500），本枪超额伤害丢弃；记录hit再split，不胜利。第二阶段在后续逻辑步受到致死伤害时，才记录hit再victory。该夹断规则是本项目为保证阶段成立的研究口径，并非宣称原作逐发伤害精确如此。若分裂与超时同一时刻发生，允许split+timeout和零时长第二阶段；不得计胜利，第二阶段质量标记zero_duration、覆盖0。评分核保持“胜利必须进入并实际经历第二阶段”的约束，并新增跨阈值/零时长测试。

弹药可行性据两阶段计算：`ceil((总血量−分裂阈值)/单发伤害)+ceil(分裂阈值/单发伤害)`。在当前草案的1000 HP、50%阈值、40伤害下，至少需要26发有效命中；只检查总伤害是否大于1000会错误放行25发的配置。当前60发为理论预算，不保证实战命中或补给可达。

`event_order.py` 是无几何的纯函数边界裁决器，仅证明以上确定性顺序；它不会自动证明抓取合法、枪口LOS、真实门体碰撞或射击伤害。Phase 2战斗引擎负责生成已验证提案，Phase 3与Godot逐项对照。其他边界输入如无效grab、门未开时命中失败和击杀/分裂同时间均有测试。

潜行者在Boss血量跨越50%时出现；必须在Boss附近找到不重叠的位置，不能瞬移到玩家盲区；短暂控制.8秒，.6秒预警、4秒冷却。此草案把玩家命中潜行者简化为打断撤退，不单独进行终战。这是代理假设而非原作精确复刻；其参数不进入Genome，Phase 3冻结前可校准。Boss死亡即胜利，出口无效；180秒为超时而非胜利。完整生命系统、酸液、制作、复杂动画不在首版评分范围。

through:玩家A挤身.65秒；Boss撞开1.5秒。break:玩家不得破坏，Boss1.8秒后双方可过。玩家不得通过一次交互全局解锁Boss的通路。block独立碰撞/视觉高度；净空、门状态、攻击LOS均需Godot检查。

成功采集每阶段：实际感知/丢失/重获目标，合法接敌时间、攻击预警、反应余量、相机与枪口判定、命中、弹药、换弹、拾取、分裂和Portal状态。Python与Godot共用字段但必须运行一致性测试，不能因字段一样就声称物理等价。

Phase 1反例是评分输入测试：安全点/补给死锁/穿墙通过注入已确认违规旗标检查不能被Q抵消，并不声称代码已从地图自动发现这些漏洞。Phase 2必须补上真实场景和几何/物理检测；Phase 3补真实事件重算测试。

正式预算32人口x(初始0代+20次繁殖)x3seedx3arm=6048评价请求。全部12局理论72576，实际早筛/缓存另计，不能补抽。搜索seed扰动0–3，独立验收101–104，不回流调参。完整调度未实现，preflight必须拒绝。

## 2026-11-22 window与多Portal扩展（待完整接通）

当前开发加入window：玩家交互翻越，可从实际开口射击；Boss不能翻越或撞开。window不等于普通门、through或可破坏墙；窗台/窗框保留高度相关的碰撞、视线与弹道遮挡。多个Portal即使连同一房间对也独立交互，开一扇不能解锁其他门。基础邻区数量按不同邻居计算。

Godot当前翻越时长初值为0.65秒，仍硬编码在实现中，尚未进入combat_config共享配置。后续需统一翻越时间、范围、净空、打断、失败恢复及动作期间射击/受击规则，并对Python代理、事件载荷和Godot逐项测试。本次文档不把这些尚未实现的细则写成已验证事实，也不改变已确认两阶段击杀规则。

Phase 2先验收新通道与实际机制，Phase 3再统一窗框高度、二维Depthmap导出近似、玩家相机感知和枪口射线的测量口径；不得将二维可见性等同实际可射击。特别测试window后的永久安全输出、Boss替代路径、翻越失败与隔窗射击，证明无漏洞后才冻结新协议。草案期校准可调整初值；正式实验冻结后变更需新版本/实验ID，不能与旧分数混排。
