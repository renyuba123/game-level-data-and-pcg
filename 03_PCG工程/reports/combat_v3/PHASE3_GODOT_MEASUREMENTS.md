# Phase 3 Godot 计分采集

Godot 在固定物理帧采集玩家与两名敌人的可见性、枪口通阻、接敌时长估计、撤离净空及动作状态。Python 从帧序列计算反应机会、资源不足与恢复、有效威胁时间、连续射击窗口、重新发现目标及动作风险。缺少过关证据时 D 保持缺失。发射位置与已打开破坏门的实际穿越从真实事件/轨迹提取，接到既有成功路线计算。资源审计验证拾取 ID、弹药守恒和胜局二阶段终局。

接敌估计采用当前 Godot 导航、接触射线与攻击前摇。撤离估计试探当前碰撞形状可通过的短位移。它们是局部估计，跨门未完成破坏、未来敌人重新规划与转角避让还需专项反例校准。导出的 60 Hz 用于时间分母。原归档批次缺这些字段时继续标记缺失。

36 局均为 180 秒超时，全部通过弹药账本检查，评分状态 UNCERTAIN。Seed 6 第二阶段的平均有效射击时间占比约 1.61%，本批没有弹药耗尽机会。Seed 84 第二阶段约 0.52%，进入第二阶段的 7 局发生弹药耗尽且没有恢复。Seed 1002 的开发校准独立场景用 101–104，各跑三策略；这些数据用于此轮诊断，最终冻结后测试仍需使用未调参的数据。

62 项 Python 测试通过，包含连续射击窗口、跨阶段资源恢复及非法资源反例。Seed 6 遮挡场景 0 的 10,800 帧和全部事件重放一致。按旧配置做 ±20% 单因素敏感性复算，三图 F 的得分范围明显重叠。当前样本不足以锁定难度或 D 的排序。复算表和批次文件的 SHA-256 见同目录索引。

下一步用固定布局和 Godot 合法控制提供至少两条成功路线，重点测后期射击与资源转移，并完成难度/漏洞反例、独立校准和尺度及协议冻结。
