# Phase 2.2 — 同场核心区、出生与补给布局

在已收录的 `full_pcg` 真实可变图和权威多边形上增加 `combat_pcg.layouts` 适配，不生成第二套几何。先从实际图中选全开度数至少3、初始玩家非break出口至少2的核心区；扩大它成为本图面积前25%的真实房间，移走核心障碍以保留开场反应空间。玩家与大型鼠王在**同一room ID**但不同坐标/朝向出生，均做角色半径净空检查，计算基于距离、Boss速度、攻击预警和玩家反应延迟的开场余量。该余量仍是二维代理，不能代替Godot攻击判定。

固定6个补给包的数量和每包弹药只取自战斗协议；Genome只记录补给位置，包分布在不同初始可达房间。出口保留为战后标记，不再是胜利条件。旧出口验证器仍被调用获取可复用的净空/撞门证据，但退出时间与绕行阈值只留作诊断，不影响Boss战有效性。实际Portal图由独立封口重建复查；布局和可移植combat-pcg/3合同都可保存重建。

运行 `python -B -m combat_pcg.phase2_audit --seeds 1:100 --output full_pcg_output/combat_phase2_audit_v1`：100次完整尝试，**98个通过几何/拓扑及开场规则**，房数8–18、96类无标签非同构拓扑、环数2–7；仅2个失败，原因均为 `no_break_shortcut`。每个seed保存Genome、Layout与检查结果。摘要SHA-256 `f3f2be58f52d487c77b8575bf5bac9df9caa71701b15593ae5b345baacfaefa3`。配置哈希和协议哈希保存在摘要。单元测试还检查同场不同坐标、固定补给数量、合同有效性、同seed Layout哈希重现、补给缺失拒绝。

**范围限制：**98%是本模块的几何/拓扑及开场条件合法率，不是可赢战斗比例。尚无射击/潜行者/真实Boss导航、Python与Godot事件一致性、角色物理或Death/Victory模拟。旧几何房间的格点布置先验与可玩面积计算方式仍待校准；被选核心区的高连通度按Room/Portal图，不等同Depthmap VGA Connectivity。完整Phase 2验收仍需Godot和事件日志。
