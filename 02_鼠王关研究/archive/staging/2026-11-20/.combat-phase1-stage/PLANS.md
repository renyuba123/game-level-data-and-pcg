# 鼠王关 PCG：可解释评分、全地图进化与逐代回放长期开发计划

**确认版本：**2026-11-20 用户批准的五阶段计划，包含“逐模块测试后 Git Commit”和“6048 次评价由本地程序自动执行”。本文件是仓库级长期规范；更新时保留已确认约束，记录协议版本与原因，不静默删减研究目标。进度见 `PROGRESS.md`。

## 1. 研究目标与执行方式

完整数据流：**可变拓扑地图生成 → 几何／通路验证 → Depthmap 空间分析及战斗模拟 → S/F/P/D 多目标评分 → 遗传进化 → Generation 0–20 离线回放 → Godot 物理验证。** 研究观察、射击、躲避、补给、重新交战、击败大型鼠王的战斗循环。轮廓或数值接近原图不自动代表体验更好；三种搜索方法不预设胜负。

五个 Phase 各为一项任务，拆为可验证功能模块。每模块先定义输入/输出/验收，复用或实现，再测试、必要运行验证、更新 `PROGRESS.md`、显式暂存并 Git Commit，然后继续下一个模块。阶段验收不过，不启动依赖该阶段的正式工作。保留已有未提交修改，不自动 push。大型实验输出留运行目录，Git 仅保存清单、哈希和小型证据；每阶段报告测试、限制、配置、来源及对应 Commit。

复用顺序：**现有实现 → 成熟开源模块 → 最小必要开发**。审查版本、许可证、依赖和测试，不整套无目的迁移。候选第三人称/射击组件为 [RoboBlast/godot-fps](https://github.com/mdtoupin/godot-fps)、[Kenney Starter Kit FPS](https://github.com/KenneyNL/Starter-Kit-FPS)；[LimboAI](https://github.com/limbonaut/limboai) 仅在潜行者状态管理确实需要时接入。本地现有移动、Boss追击、碰撞、挤身、破坏、Depthmap CLI、缓存、pymoo多目标选择、二维图表优先复用。

保留 Legacy、`evolution/runs/search_v1`、原 DXF、`shuwang.graph`。新战斗协议与旧逃生评价完全分版。新系统的 Python Layout 是唯一几何来源；二维预览、Depthmap、Python代理和Godot读取同一布局。所有正式评价由 Python 调度，DepthmapX 输出真实空间指标，Godot按冻结协议验证；Codex仅编写、调试、检查证据与报告，不逐地图评分或决定遗传生存选择。程序须能在对话关闭后运行与恢复。

## 2. 数据合同与战斗口径

接口：`generate(genome, config) → Layout + ValidationReport`；`analyze(layout, config) → SpatialResults`；`simulate(layout, combat_config, seed) → EpisodeLog`；`score(layout, spatial_results, logs, scoring_config) → ScoreReport`；`load_layout(layout) → Godot 2D/3D`。

Genome含稳定房间ID、功能、局部轮廓、位置、旋转、连边、普通/through/break门、障碍、同场出生和补给位置。Layout含实际房间/走廊多边形、地板、墙、Portal、遮挡、出生、拓扑实现映射。Individual出现ID与内容哈希分离；保留父代、算子、修复、评价。Generation分别保存新子代和选择后的全部种群、当前/累计Pareto、展示代表与各目标历史最优。坐标为Godot X/Z模型米；Depthmap图纸单位转换显式记录。日志含版本、配置/来源哈希，原始事件、时间、位置、视域、射击/伤害、换弹、拾取、破坏、分裂和终止状态。评分器与模拟器分离，能凭原始日志复算。

玩家与大型鼠王在**同一个真实连续核心空间**出生，ID相同但位置和朝向不同。核心空间面积在功能房间前25%，全开时连接至少3邻区，初始至少2条玩家可用离开路径；按合法路径和攻击时序验证开场反应余量。核心区不必在几何中心，也不复制原图外轮廓。固定武器、血量、速度、角色尺寸、攻击与分裂阈值，不让遗传算法调整角色强弱。初始弹药、总补给及包数固定，仅补给位置进化，拾取耗时、不刷新。

胜利=大型鼠王死亡；失败=玩家死亡；超时独立记录，出口只作战后离场标记。Boss低于固定血量阈值后分裂潜行者，后者潜伏、接近、预警攻击、短暂控制、撤退；本轮不生成原作后续独立潜行者终战场地。through玩家按A挤身、Boss耗时撞开；break仅Boss破坏，之后双方可通过；block是障碍而不是连接。感知严格区分Depthmap潜在可见性、玩家相机实际视域和枪口弹道；双方不能透视未知位置。二维代理用固定seed进行廉价评价，Godot核对实际碰撞、LOS、导航、射击和状态事件。首版无需完整动画、美术、复杂UI或完整游戏武器库。

## 3. 全地图生成与合法性

拓扑层默认8–18个功能房，走廊和交叉口另记；支持房间增删、边重接、环路增删、多个核心、支路、瓶颈、死路、捷径与绕行。through默认2–8、break默认1–5，按可用边限制。空间规则可配置，保留核心风险、遮挡、开放/压迫变化、可预测但不绝对安全的转移、破坏后的连通变化，而非固定11房模板。

几何层支持不同长宽比、矩形、削角、梯形、斜边、L形及凹口；独立位置/尺寸/45度旋转；使用多边形净距、确定性走廊A*、门洞边界定位和角色净空。未声明的走廊交汇、穿第三方房间、贴墙隐藏开口均无效；真实交叉口要显式记录。修复最多8轮，失败保留原因，不退回固定模板。地板、墙、碰撞、障碍和两角色导航取自同一轮廓。基准可玩面积0.75–1.25倍，必须先统一扣墙/障碍/开口口径。

廉价过滤先于Depthmap：多边形/墙/门合法、房间无非预期重叠、实际几何图与目标拓扑一致、角色净空与出生合法、初始/全开/代表破坏中间状态、Boss可逐步到达撞击面、全开后必要区域对双方可达、无短路和异常绕行。再区分战斗可行性：有反应、射击、资源与反制证据。几何 INVALID、战斗 UNCERTAIN、系统 ERROR 分别记录；12局未获胜不证明地图不可能获胜。

100固定seed工程目标：几何/拓扑合法率>=80%；合法样本至少5种房数、10个精确非同构基本拓扑、3种环数，含旋转和非矩形。完整报告尝试、修复和失败，不只展示成功。变异包括房间/边增删、环路、轮廓/尺寸/位置/旋转、门、障碍、同场出生和补给。子图交叉处理1–3边界接口，失败记录后有限回退单亲变异。默认交叉概率0.8，每子代1–3变异，拓扑与几何/玩法约各半。pymoo仅复用非支配/拥挤度及约束选择；不能将可变图强塞旧77参数交配。

## 4. 评分协议、证据和防刷分

硬约束先于软分：几何、通路、碰撞、净空、门角色规则、出生、补给可达、合法伤害/拾取、相同固定资源预算，排除敌人不能反制的永久安全射击位置。理论弹药伤害要足够；是否已有获胜证据单独表示。统一状态VALID／INVALID／UNCERTAIN／ERROR，并附具体原因；ERROR不能当低分地图，UNCERTAIN不能当已证明无解。

四目标0–100越高越好，最小化`[-S,-F,-P,-D]`：

| 主分 | 子项与内部权重 |
|---|---|
| S：战斗空间结构质量 | 全局真实空间指标分布50%，功能区域指标分布50% |
| F：公平性与资源 | 获胜率目标适配50%，反应余量25%，补给可获取性25% |
| P：压力与视域节奏 | 有效威胁35%，有效射击窗口30%，丢失/重获目标20%，换弹/拾取风险15% |
| D：有效战术多样性 | 成功路线差异35%，交战位置分布25%，替代路径实际使用25%，破坏后的战术变化15% |

展示总分`Q=0.15S+0.35F+0.30P+0.20D`，不参与遗传生存选择或掩盖硬约束。旧结构距离另命名保留，绝不与新版S混用。S比较空间组织和功能，不比较坐标/外轮廓。Connectivity用可见点比例，Metric除以可玩面积平方根，Integration保留定义并用固定基准尺度比较分布；初始与全开分开计算。功能类别由几何/实际连接复算，不能仅改标签降损失；Gate Counts和Convex Choice校准前排除。统一网格与基准尺度，不逐候选各自归一化。

F的标准代理胜率50%–80%仅为待校准初始设计区间，高胜率不直接等于不公平。反应余量=从可感知威胁到攻击命中的时间-代理反应及合法躲避时间。补给按需要时是否安全取得评估。P按合法路径、攻击条件和破坏时间计算压力，不以隔墙直线距离或单纯靠近代替；射击窗口需相机可见、枪口畅通、瞄准/射击时间足够且仍能转移。D按固定米制网格、成功路线和真实替代路径计算，不能靠拆房间、开无用门或无限绕圈刷分。潜行者分裂前后分别报告；缺阶段、早死、零机会、少量胜利都按事前规则记录，不删失败局、不造零值、不从不同个体拼冠军。

每个子指标必须有变量/公式、单位、采集、有效范围、最优区间、惩罚/归一化、权重、缺失/极端处理、手算例和测试。区间型可用`q(x)=100 max(0,1-distance(x,[L,U])/τ)`。所有权重、阈值、尺度、终止、样本门槛与配置在正式搜索前冻结，变动新开实验。反例覆盖永久安全输出、无反击狭区、补给死锁、零伤害绕圈、穿墙/透视、早死分母漏洞、无意义拆房和缺第二阶段高分。人工样例不等于模拟数据。

## 5. 五阶段、模块提交与验收

**Phase 1 — 复用审查、评分规范、协议草案。** 模块1.1仓库/开源/许可审查；1.2版本化数据合同；1.3可复算评分核、公式、手算样例、边界/反例单测；1.4固定武器/敌人/资源/通道草案、反例入口和阶段验收。每模块测试通过更新进度并Git提交，阶段报告关联提交。通过门槛：计算方向、来源与异常清楚，代表样例可手算。所有未校准数字明确是实验假设。

**Phase 2 — 全地图生成与最小战斗闭环。** 模块：真实可变拓扑/几何/通路重建；同场核心区和补给；复用射击/追击/破坏/潜行者；统一Python/Godot事件；保存/重建/2D预览；100seed审计和代表Godot测试。达到前述80%/房数/同构/环数门槛。几何、拓扑、战斗证据各报告，不把未获胜当几何错误。

**Phase 3 — 战斗代理、反例、校准与冻结。** 搜索策略：输出优先、遮挡转移、补给优先，每类4组固定扰动，12局/候选；同候选条件固定，随机流按事件类别派生。基准白模、独立样本及反例校准；Godot与Python核对可见、命中、伤害、弹药、Portal、分裂和胜负。另用未参与搜索的起点、随机种子和能力配置独立复核，做阈值/权重敏感性；追加样本另计预算、不与12局分数混排。冻结配置、源码/工具/基准哈希和明确Commit。通过门槛：合理、过难、无聊和漏洞地图分数可解释，结论对合理扰动不过度敏感。

**Phase 4 — 自动进化、完整代史、离线2D回放。** 先小种群2次繁殖，检查生成→验证→Depthmap→模拟→评分→选择→算子闭环，以及固定seed、并行完成顺序、中断恢复、缓存、谱系/fitness。正式单seed Generation0初始32个，加1–20代各32次繁殖，共672候选评价请求。记录所有子代、完整幸存种群、修复/错误、当前和累计Pareto、代表及各目标独立历史最优。提交采用原子写入，只恢复完整代。基础Viewer在正式搜索前完成：代滑块、前后/播放、种群及无效筛选、S/F/P/D原始证据、Pareto轴、父子/操作、双面板与拓扑、合法候选3D加载。当前代表采用明确固定规则仅供展示，不称全面最优。统一地图坐标比例；真实每代PNG、父子差异、射击/死亡/补给/视域、破坏/分裂前后与GIF/MP4，标注样本和分母；不插值制造血缘。

**Phase 5 — A/B/C对照、消融、独立验证。** A=Legacy固定拓扑+旧混合变量GA，B=Full-PCG+结构化GA，C=Full-PCG+独立随机。B/C同Genome初始分布/修复/评价，A要适配同战斗协议，否则报告不可比。3组×3seed×672=**6048候选评价请求**；若全部执行12局理论为72576局战斗模拟。无效、重复、缓存命中照计请求，不补抽；系统ERROR恢复同请求，不换个体；额外复核/消融独立预算。分别报告请求、唯一Genome/Layout、真实模拟、Depthmap调用、缓存、修复成本与CPU/墙钟，并按共同CPU时间截点比较。报告合法率、战斗支持率、拓扑多样性、S/F/P/D、固定尺度/参考点超体积、当前/累计档案、独立能力稳定性；消融优先去S/P/D，记录完整指标。选至少12张不同房数/拓扑/特殊通道的合法候选做Godot实际穿门、射击、导航和战斗检查。三seed只提供初步重复性，不能自动宣称统计显著或优于官方；真人试玩另行验证体验。

## 6. 自动运行与最终交付

目标入口：`python -m full_pcg generate --config ... --seeds 1:100`；`python -m full_pcg experiment --config ... --resume`；`python -m full_pcg export --run ... --figures --gif --mp4`；`python -m full_pcg verify --run ...`。自动进程需日志、超时、有限重试、缓存、原子检查点、配置/版本校验；Godot全量或抽样验证口径在正式协议冻结。尚未实现的入口不得宣称可用。

最终验收：真实拓扑变化；几何/拓扑/战斗/系统失败区分；S/F/P/D可从原始日志复算；完整Pareto和Generation0–20；离线任意代/个体、父子和跨代回放；Godot重建合法候选；实际视频/行为图；固定种子、并行/恢复一致；A/B/C及消融/计算成本；阶段模块测试、Git提交与验收报告；6048请求由本地程序独立完成。最终报告分别说明物理测量、空间句法、代理模拟、Godot验证和真人体验假设。
