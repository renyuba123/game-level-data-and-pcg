# 首次案例：TLOU Part II Rat King 玩家轨迹图（基于用户截图）

## 已观察到的内容（仅外观层面）
- 当前图包含灰色墙体/门洞、浅蓝/粉/青/黄/紫的空间分区、黑色细玩家路线、许多彩色三角形/方形/圆形等事件符号。
- 右侧 Illustrator 图层列表可见 `Spawn`, `Death`, `Break`, `Brick`, `Crossbow`, `Hunting Pistol`, `Pistol`, `Shotgun`, `Rifle`, `Pipe Bomb`, `Health damage`, `Melee`, `Flamethrower`, `Transform`, `Route`, `Base`, `depthmap` 等名称；可能存在重复 `Break`，必须读真实文档核对层及子对象数量。
- 黑色路线与墙体线视觉接近，多条长线在中央通道交叉，缺乏明确行进方向/轨迹先后顺序。
- 彩色块似乎是空间分区的表达，但没有可信的属性数字、图例，不能自动判定其为 Connectivity/Choice/Integration/Depth 的测量结果。

## 第一轮改良任务（不移动几何）
1. 另存带日期及 run_id 的工作副本，保留 source 原件与 AI 所有原图层。
2. 将墙体设置为可读的中性深灰；将空间分区改为低饱和、低透明度填充，确保门洞清晰，主图路线最突出。
3. 将 Route 的**显示样式**统一为高对比度蓝色（例如 #147DCE，约 2–3 pt，随最终图幅调整），但暂不重新排序、合并或简化原路径对象。
4. 保留现有事件原始符号，额外制作可独立编辑的 `Legend` 图层，文字来自用户确认的事件映射。未确认 `Break`、`Transform`、`Crossbow` 语义时标“待确认”。
5. 如没有可靠轨迹时间序列：不要画假箭头。添加 `Sequence Review` 图层，列出需要用户根据录像确认的轨迹段 ID / 事件 ID / 大致区域。标注疑似穿墙长直线为“待核验”，不自动修正。
6. 原来总览图拆分输出：
   - 图 A `Movement Trajectory`：建筑 + 区域编号 + 路线 + 起终点 + 已验证方向/时序；
   - 图 B `Combat Event Map`：建筑 + 淡色路线 + 事件标记 + 图例；
   - 图 C `Space Usage / Choice Overlay`：仅在存在已核准拓扑、可量化路线使用数据时输出。
7. 逐一检查截图中通道拐角、右侧房间周围及中央大跨度直线是否真正沿可通行区域经过；线与墙重叠不能凭截图判断为非法穿墙。
8. 输出一份 `QA_REPORT.md`，列出可验证结果与尚缺少的录像时间、图层语义、比例基准。

## 推荐分析问题（不是预设结论）
- 当前图上的上方主通道及右侧狭窄通道是否被重复穿越？
- 左侧大空间与下方大空间之间是否有多次往返、可核实的环路？
- 武器使用点、受伤点在各凸空间的事件率如何（若已确认事件含义与空间边界）？
- 玩家实际通道使用频率是否与 Choice 数值一致？不一致可能与敌人位置等动态因素有关。

## 重要边界
单局地图不能证明普遍玩家行为。若用户把路线点作为“使用一次武器”的标记，与“拾取武器”不能混淆。若录像含多次死亡重试，需要区分 `attempt_id`，不能把不同 attempt 的路线拼作一次连续存活过程。
